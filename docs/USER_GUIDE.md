# Espetro 使用手册

## 安装与第一次启动

客户端和服务器使用相同的 Forge 1.20.1 模组组合。基础运行需要 Espetro、MUtil、OELib、AuraTip、Rhino、
Architectury API 与 KubeJS；需要战术地图和据点时还要安装本工作区同步版 ESPoints。

第一次完整启动会在游戏或服务器根目录生成：

- `EsDimensions.json`：地图列表和投票时间；
- `EsFactions/`：编制示例；
- `EsWorld/test_flat/`：可直接投票测试的超平坦地图；
- `kubejs/`：默认指挥官技能脚本。

示例只补缺失文件，不会覆盖服主已有内容。修改地图、编制或 `EsConfig` 后需要完整重启。

## 一局游戏

1. 管理员在主城开始地图投票。
2. 所有在线玩家在卡片式界面中选择地图。
3. 地图获胜后，系统从 `EsWorld` 模板创建本局临时战场。
4. 玩家选择进攻方或防守方。
5. 双方依次选出指挥官；无人投票时随机指挥官也会进入同一治理状态。
6. 指挥官选择本方编制，双方编制随后公开。
7. 玩家在统一部署界面选择班组、职业和部署点。
8. 进入战斗后，占领据点并消耗敌方兵力。
9. 回合结束后所有玩家返回主城，临时战场被卸载和删除。

战斗前的普通选择界面允许玩家按 Esc 关闭；必须作出选择的选边界面会保持打开。部署主界面仅在玩家尚未选定部署点时强制锁定；选定部署点后即可 Esc 关闭，之后仍可按 J 重新打开以调整班组或职业。

## 主要界面

### 主城

主城界面提供当前状态和新手教程入口。新手教程逐页介绍地图投票、选边、指挥官、编制、班组职业、部署、据点和战斗，不要求玩家记忆管理命令。

### 地图投票

地图以多列卡片显示，包含地图名、当前票数和简图。再次点击可以改变选择；投票结束后服务端决定结果，平票时随机选择。

### 指挥官与编制

指挥官候选人由本阵营玩家投票产生。无人主动参选或无人投票时，系统会随机补位；随机产生的指挥官与正常当选者一样，可以在战斗阶段被弹劾。

编制选择使用卡片布局展示候选编制。编制决定本方职业、载具和部分部署内容。

### 统一部署界面

左栏选择班组，中栏选择职业和部署点，右栏显示战术地图。班组名称不再带内部数字编号。小队类别弹窗采用紧凑二级菜单，不遮挡整个界面。

战术地图底部提供“玩家分数板”和“发起弹劾”入口。弹劾按钮只在战斗阶段且当前没有其他治理投票时出现。

### 战术地图与据点

战术地图范围、底图、网格和据点都来自当前地图的 `EsConfig`。指挥官和小队长可在当前战场内放置同阵营标点；指挥官技能目标也只能从当前战场提交。地图切换或强制结束后旧标点不会保留。

兵站只有处于同阵营 Radio 的建造范围内时才会显示；Radio 被收起或摧毁、导致兵站失去覆盖后，该兵站会自动从战术地图移除。

战场中的已部署玩家视为挖掘等级不足，无法开采任何方块（不再使用挖掘疲劳）。敌方 Radio 不使用普通挖掘：靠近后潜行并左键点击即可开始拆除，留在 Radio 附近等待 30 秒后完成；死亡、离开附近或阵营状态改变都会取消。己方 Radio 仍由本方小队长或指挥官潜行左键立即收起。

每次成功选择职业后会进入该地图配置的个人换职冷却。重复点击当前职业不会重新计时；离开班组、死亡或短线重连不会清除尚未结束的冷却。

## 班组、职业与部署

- 先加入或创建班组，再选择该编制允许的职业。
- 每个小队最多 9 人，按 A、B、C 三个火力组依次填充，每组最多 3 人；每组第一个成员自动成为火力组组长。
- 小队长固定是 A 组组长。小队长可在 J 键界面左侧右键队员，转移队长或将队员调整到 A/B/C 组；火力组组长可右键同组队员转移组长。确认菜单和交互均使用 MUtil。
- 绿色数量表示仍有名额，红色表示已满。
- 编制可用 `teammates_need` 要求某职业达到指定小队人数后解锁；人数不足时按钮会直接说明原因。
- 部署点包括原部署点、有效兵站/HAB、队包和载具出生点，实际可用项由服务端决定。
- 双方最终编制确定后，系统会在编制揭示期间异步预热载具出生区块，并在布防阶段开始、玩家进入战场前，按编制 `vehicles.*.entity` 的每个配置槽位预部署一辆首发载具。重复阶段事件不会重复刷车。
- 首次部署、死亡重新部署和主动重新部署时，都会以冒险模式临时送到本方原部署点，同时保持失明、无敌、锁位和“等待选择部署点”状态。该临时落点不算选择了原部署点；仍须先选好职业，再明确点击一个部署点并确认。尚未选择阵营的玩家仍处于高空旁观等待。界面会保留当前选择，不会因频繁网络同步反复重建。
- 右键己方 Radio 可打开轮盘：变更职业、存入补给和弹药、补充弹药和补给。点击“变更职业”会在父轮盘关闭后打开职业轮盘；职业名称、图标、`[当前人数/上限]`、红色不可选状态和灰色冷却状态与 J 键界面一致。多变体职业继续进入装备变体轮盘，不显示模型预览；返回槽位使用 `↩` 回车箭头。
- 弹药补给先计算玩家的实际弹药缺口：已满时不发物品、不扣 Radio 库存且不进入冷却；Radio 必须能足额支付职业配置的 `ammo_cost`，库存不足时整次取消，不再先发弹药再把库存扣到零。
- 玩家只能在三种情况下选择职业：尚在部署界面选择部署点、位于本方原部署点 6 格内、通过附近己方 Radio 的职业轮盘。普通兵站、前哨和上一次选择的部署位置不再允许从 J 键界面换职。
- 本方原部署点周围默认 `150` 格为安全区。安全区按水平距离计算，玩家及所属本阵营的 Espetro/SBW/DragonRise/FCP 载具不会受到伤害；敌方玩家不会因为进入你的原部署点而获得保护。范围由地图 `EsConfig/game.json` 的 `game.main_base_invulnerability_radius` 控制，设为 `0` 可关闭。
- Alt 战术轮盘的“后勤”页只保留“查看 Radio 状态”；存入补给仍通过右键 Radio 的专用轮盘或潜行右键 Radio 完成。

## 战术标点

战场内按住 Ping Wheel 的标点键会打开 AuraTip 战术轮盘。指挥官、小队长、A/B/C
火力组组长，以及合法载具席位可以使用；普通队员仍可在战术地图查看同阵营标点。

- 坦克允许 0、1、2 号座位。
- 步战车/APC 与直升机允许 0、1 号座位。
- SBW、Dragonrise 和 FCP 的载具共用 SBW 载具数据类型，因此按上述类型与座位统一判断；其它载具类型和席位没有权限。
- 轮盘选择后使用 Ping Wheel 的射线、距离设置、方向提示、音效与距离缩放；标点类型和图标与战术地图一致。
- 标点由服务端校验并只同步给同阵营战场玩家。普通增删使用增量包，地图切换或强制结束会清空全部旧标点。

## 指挥官弹劾

战斗阶段可从战术地图底部发起弹劾。系统按当前指挥官建立投票：

- 正常投票当选和无人选择时随机产生的指挥官都可被弹劾；
- 同一时刻只运行一项治理投票；
- 投票结束或超时后界面自动更新；
- 指挥官离任后按地图治理配置进入空缺和冷却流程。

## 管理员操作

常用管理入口：

```text
/espetro prestart
/espetro stop
```

`prestart` 从主城开始一局。`stop` 可在任意阶段强制结束：

1. 停止当前阶段和投票；
2. 将所有在线玩家送回主城；
3. 清理队伍、班组、职业、兵站、载具、据点、标点和临时状态；
4. 不保存本局地形破坏，卸载并删除当前存档中的战场维度目录；
5. 下一局从 `EsWorld/<地图>` 只读模板重新复制。

不要把对局后的战场维度目录当作地图源，也不要在运行中的临时维度里制作模板。应在独立世界中完成地图，然后关闭服务器，将完整世界文件复制到 `EsWorld/<地图>/` 并配置 `EsConfig/`。

## 常见问题

### 地图不出现在投票中

查看启动日志中的拒绝原因。常见问题是缺少 `level.dat`、非空 `region/`、任一必需
`EsConfig` 文件，或战术地图/据点 JSON 不合法。

### 地图一直加载或实体卡住

确认服务器和客户端使用同一组模组，并使用当前构建。新版屏障只建立战场外围墙，不再一次性铺设大面积顶棚；地图复制和维度挂载不会在每个 Tick 重复执行。

### 第二局仍看到上一局破坏

应使用 `/espetro stop` 或正常结算完成清理，并确认日志显示临时战场已卸载删除。原始模板始终位于根目录 `EsWorld/`；当前存档内的维度只是一次性副本。

### 战术地图显示“不可用”

确认客户端和服务器都安装同步版 ESPoints，并检查该地图的 `TacticalMap.json` 和
`CapturePoints.json`。两份文件必须在服务器启动前已经存在且通过校验。

配置字段的完整说明见 [CONFIGURATION.md](CONFIGURATION.md)。
